# KBO 투구 제구 성공 확률 예측

데이콘 / LG Aimers 9기 온라인 해커톤. 투구 하나가 **제구 성공**일 확률을 예측한다.
평가지표는 Brier Skill Score.

```
Score = max(0, 100000 x (1 - Brier / (r(1-r))))     # r = 평가 데이터 실제 평균 성공률
```

**현재 리더보드 990.9528** (`aimers_tuned_ensemble.ipynb` v5).

## 구조

```
aimers_tuned_ensemble.ipynb   본 학습. 이 저장소에서 제출물을 만드는 유일한 노트북
CLAUDE.md                     설계 근거 · 실패 기록 · 함정 모음 (가장 중요한 문서)
tools/                        투수 매핑 재구축, 공식 베이스라인 재현
experiments/                  진단 · 스크리닝 노트북 (README.md 에 결론 요약)
data/                         원본 데이터 (git 제외)
```

전처리는 `STEPS_SRC` 문자열 하나에 정의해 학습 노트북과 제출용 `script.py` 가 **같은 소스**를
공유한다. 실험 노트북들도 이 파이프라인 셀을 그대로 떼어다 쓰므로 피처는 항상 동일하다.

## 접근

- **CatBoost** 10-fold x 3-seed = 30개 모델 평균, fold 별 isotonic 보정
- **조건부 투수통계** — 시즌 디트렌드 + 0 으로 shrink 한 (투수 x 카운트 x 좌우) 성공률
- **트랙맨 매핑 재구축** — 주최측 제공 매핑이 약 91% 틀려 있어 팀→투수 2단계로 다시 만듦
- **재중심화** — 시즌별 성공률 하락(.5647 → .4861)을 학습 시점에 측정한 로짓 상수로 보정

## 방법론 메모

이 프로젝트에서 가장 비싸게 배운 것들이다. 자세한 근거는 `CLAUDE.md`.

- **검증 지표는 반복해서 낙관적이었다.** 축약 스크리닝 → 누수 없는 홀드아웃 → 리더보드로
  갈수록 값이 줄고, 두 번은 부호까지 틀렸다.
- **오프셋 측정 셀에 ±13 실행 노이즈가 있다** (CatBoost GPU 비결정성). 한 번 돌려서
  ±26 안쪽이면 아무것도 못 읽는다. 같은 실행 안에서 짝지어 뺀 델타만 믿을 수 있다.
- **그 행 안에서 계산되는 파생피처는 트리가 스스로 만든다.** 값어치가 나온 것은 전부
  "그 행 밖에서 가져온 집계"였다 (조건부통계 +27, 트랙맨 +9, 나머지 51개 ≈ 0).
- **기준점**: 공식 베이스라인(RandomForest, 원본 47컬럼)이 같은 2024 홀드아웃에서 415.6,
  이 파이프라인이 795~803.
